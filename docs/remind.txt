思路：针对安工小智仅支持单轮检索式应答，且回答局限于制度条文，无法结合个人课表与作息相结合，只能被动等待提问——本项目开发“安答：校园AI Agent助手”，将Agent架构引入校园场景。学生通过网页以自然语言导入课表、设置提醒、发起咨询，系统自动完成意图识别、任务拆解与工具链调用；服务端采用云端 GLM API 与本地 Ollama 模型混合部署——通用咨询问答经本地模型处理，而课表、作业、考试、复习计划等复杂任务则通过云端调用以保证准确度。在每节课前进行主动提醒，实现从“被动问答”到“主动服务”的升级。
创新点：1. 场景创新——从“被动问答”到“主动服务”：系统根据课表，在每节课前自动根据场景提醒，提高用户效率
2. 技术创新——从“单轮检索”到“Agent 编排”：引入意图识别、任务拆解与工具调用的 Agent 架构，通过多样的工具链辅助用户以提供学习与生活上便利。

一款基于 RAG 知识库与云端/本地双模型混合部署的网页端校园 AI Agent，以提醒设置、复习计划、办事查询，可进行文件格式转化
半天实验，终结这场争论
别停留在“可能吃力”，周一就做这个测试：从教务系统截20张真实课表+写20条提醒指令，分别喂给GLM-4-9B和Qwen2.5-7B（Ollama直接拉），统计课表字段抽取准确率和时间解析准确率。半天出结果。测出来90%+，架构争论结束、数据进申报书；测出来70%，那就调模型/调prompt，或把该任务划入授权升级清单——无论哪个结果，你都拿到了一个别人没有的东西：实测数字。这正是我第一轮说的“把名词做成数据”，只不过这次是把架构选型做成数据。
