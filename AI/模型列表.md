# 模型列表（按性能从强到弱）

> 数据来源：硅基流动（SiliconFlow）+ GLM 官方（智谱 BigModel）+ 本地 Ollama
>
> ## 能力权重说明（核心机制）
> 每个模型的 `ability` 不再是简单标签数组，而是 **`能力名: 权重`** 映射（权重 1-10）：
>
> ```json
> "ability": {"chat": 9, "tool_use": 10, "code": 9, "reasoning": 9}
> ```
>
> - **只登记该模型真正具备的能力**（没写的能力 = 不参与该能力路由）
> - **权重 = 该能力下的调用优先级**：请求某能力时，所有具备该能力的模型按权重**从高到低依次调用**，
>   第一个成功即返回——权重本身就编码了 fallback 顺序，无需再手写 fallback 链
> - 同权重时按注册顺序调用
> - `default: true` 只作为"没有任何能力匹配"时的最终兜底
>
> 能力标签含义：
> `chat` 对话 / `tool_use` 工具调用 / `code` 代码 / `reasoning` 深度推理 / `math` 数学 /
> `vision` 视觉理解 / `ocr` 文字识别 / `long_context` 超长上下文 / `offline` 离线可用
>
> ⚠️ 接口类型说明：
> - LLM 类（一、二节）走 `/chat/completions`，注册进 model.json 由统一网关调用
> - 专用模型（三节：语音/翻译/文生图/嵌入）走各自专用接口，由对应工具直连，不进统一路由

## 一、通用对话 / 推理 LLM（主力路由池）

### 1. GLM-4.7-Flash（zhipu）⭐ 推荐 default
- 深度思考 复杂推理和工具使用的能力强大
- 能力权重：`{"chat": 9, "tool_use": 10, "code": 9, "reasoning": 9}`
- 性能评价：GLM 官方新一代 Flash 旗舰，深度思考 + 工具调用全列表最强，`tool_use` 权重 10 → function calling 主路径首选

### 2. XingChenAGI/Xing4.0-29B（siliconflow）
- Xing4.0-29B-A4B让百亿参数模型从"会写代码"迈向"能干工程"，总参数量为29B，单次激活参数量为4B。全国产开源，原生支持256K，外推可达512K超长上下文，兼具复杂推理、工具调用与长程任务执行能力。基于昇腾算力训练，支持私有化及消费级单卡部署
- 能力权重：`{"chat": 9, "tool_use": 8, "code": 8, "reasoning": 8, "long_context": 10}`
- 性能评价：29B + 256K 上下文，`long_context` 权重 10 → 长文档/长程任务首选；各能力均衡偏强

### 3. deepseek-ai/DeepSeek-R1-0528-Qwen3-8B（siliconflow）
- DeepSeek-R1-0528-Qwen3-8B 是通过从 DeepSeek-R1-0528 模型蒸馏思维链到 Qwen3 8B Base 获得的模型。该模型在开源模型中达到了最先进（SOTA）的性能，在 AIME 2024 测试中超越了 Qwen3 8B 10%，并达到了 Qwen3-235B-thinking 的性能水平。该模型在数学推理、编程和通用逻辑等多个基准测试中表现出色，其架构与 Qwen3-8B 相同，但共享 DeepSeek-R1-0528 的分词器配置
- 能力权重：`{"chat": 7, "code": 10, "reasoning": 10, "math": 10}`
- 性能评价：8B 级推理/数学/代码之王；**不支持 function calling，刻意不配 `tool_use`**，永远不会被 FC 管线选中

### 4. Qwen/Qwen3-8B（siliconflow）
- Qwen3-8B 是通义千问系列的最新大语言模型，拥有 8.2B 参数量。支持在思考模式（复杂逻辑推理、数学和编程）和非思考模式（高效通用对话）之间无缝切换。在数学、代码生成和常识逻辑推理上表现优异，支持 100 多种语言和方言
- 能力权重：`{"chat": 8, "tool_use": 7, "code": 8, "reasoning": 8}`
- 性能评价：思考/非思考双模式，各能力第二梯队，常任 fallback

### 5. THUDM/GLM-4-9B-0414（siliconflow）
- GLM-4-9B-0414 是 GLM 系列的小型模型，拥有 90 亿参数。继承了 GLM-4-32B 系列的技术特点。在代码生成、网页设计、SVG 图形生成和基于搜索的写作等任务上展现出色能力。支持函数调用功能
- 能力权重：`{"chat": 7, "tool_use": 8, "code": 9}`
- 性能评价：代码生成与 FC 稳定（`code: 9` 仅次于 DeepSeek-R1），GLM-4.7-Flash 的同门备胎

### 6. Qwen/Qwen3.5-4B（siliconflow）
- Qwen3.5-4B 是通义千问团队推出的原生多模态大语言模型，拥有 4B 参数。原生支持 256K 上下文长度，并可扩展至约 100 万 tokens。通过早期融合训练实现了统一的视觉语言基础能力，支持文本、图像和视频理解，多项指标超越 GPT-5-Nano 和 Gemini-2.5-Flash-Lite。默认启用思考模式，支持工具调用
- 能力权重：`{"chat": 6, "vision": 6, "tool_use": 6, "code": 6, "long_context": 8}`
- 性能评价：4B 但原生多模态 + 百万级上下文扩展；参数量小，各能力权重居中，`long_context` 是第二选择

### 7. GLM-4-Flash-250414（zhipu）
- 文本生成 支持基于自然语言的语义理解、内容生成和多轮对话
- 能力权重：`{"chat": 5}`
- 性能评价：轻量免费对话，无深度推理，闲聊兜底

### 8. GLM-4-Flash（zhipu）
- （GLM-4-Flash-250414 的旧版本，能力相同：自然语言语义理解、内容生成、多轮对话）
- 能力权重：`{"chat": 5}`
- 性能评价：与 250414 同权重同级，**建议二选一注册**，另一个作 chat 层的最后兜底

### 9. mimo9b（ollama · 本地）
- 本地 Ollama 部署的小米 MiMo 系列推理模型（9B），通过 Ollama 的 OpenAI 兼容端点 `http://localhost:11434/v1` 接入，无需 API Key，断网或云服务欠费时仍可正常工作
- 能力权重：`{"chat": 3, "tool_use": 3, "code": 4, "reasoning": 5, "offline": 10}`
- 性能评价：**能力权重为保守估计，建议本地实测后调整**。日常路由中云模型按权重排在其前，几乎不会被选中；
  核心价值在 `offline: 10`——云模型全部不可用时它是唯一幸存者。本地推理无需联网，但受限于本机算力，响应速度和生成质量弱于云端模型

## 二、视觉理解模型（vision / ocr 路由专用）

### 10. GLM-4.6V-Flash（zhipu）
- 视觉理解 提供高精度的多模态推理和交互能力
- 能力权重：`{"vision": 10, "chat": 6}`
- 性能评价：`vision` 权重 10 → 图片理解工具（image_understand）首选

### 11. deepseek-ai/DeepSeek-OCR（siliconflow）
- DeepSeek-OCR 是由深度求索（DeepSeek AI）推出的一个视觉语言模型，专注于光学字符识别（OCR）与"上下文光学压缩"。能够高效处理文档并将其转换为如 Markdown 等结构化文本格式
- 能力权重：`{"vision": 7, "ocr": 8}`
- 性能评价：OCR + 文档转 Markdown 专精，3B 轻量高吞吐

### 12. PaddlePaddle/PaddleOCR-VL-1.5（siliconflow）
- PaddleOCR-VL-1.5 在文档解析权威评测集 OmniDocBench v1.5 上取得 94.5% 的精度，超越全球顶尖通用大模型与文档解析专用模型。创新支持文档元素的异形框定位，在扫描、倾斜、屏幕拍摄等真实场景下表现稳健。集成印章识别与文本检测识别任务
- 能力权重：`{"ocr": 10, "vision": 5}`
- 性能评价：纯 OCR 精度 SOTA（`ocr: 10`），但不是对话模型，`vision` 只给 5 作勉强可用

## 三、专用模型（工具直连，不进统一路由）

### 13. XingChenAGI/XingChenASR-V3.2-Ultra（siliconflow · 语音）
- XingChenASR V3.2-Ultra 面向工业级场景深度优化，支持中+英+60种方言混合识别。普通话朗读 AIShell2 字准确率达 97.25%，英语通用基准 librispeech_clean 准确率达 98.04%
- 能力权重：`{"asr": 10}`　|　ASR 精度天花板，60 种方言

### 14. XingChenAGI/XingChenASR-V3.2（siliconflow · 语音）
- 中国电信星辰语音识别大模型，业内首个中英文及30种方言自由混说技术范式，支持方言已达60种。普通话朗读（Aishell2）字级别准确率 97.25%，月调用量超4亿次
- 能力权重：`{"asr": 8}`　|　Ultra 的标准版

### 15. XingChenAGI/XingChenASR-Diarize-V3.0（siliconflow · 语音）
- XingChenASR-Diarize V3.0 针对会议场景深度定制，说话人分离准确度行业领先。英文通用场景准确率达 93.33%，近场会议场景可达 97.13%
- 能力权重：`{"asr": 7, "diarize": 10}`　|　会议转写 + 说话人分离专用

### 16. XingChenAGI/XingChenGSR-V1.0（siliconflow · 语音）
- XingChenGSR（生成式语音识别）深度融合大语言模型的上下文理解能力，在完成语音识别的同时开展语义层面智能优化，直接输出更贴合人类表达逻辑的高质量转写文本
- 能力权重：`{"asr": 6, "semantic_asr": 9}`　|　语义优化转写

### 17. FunAudioLLM/SenseVoiceSmall（siliconflow · 语音）
- SenseVoice 具有 ASR、口语语言识别、语音情感识别和音频事件检测能力。非自回归端到端框架，支持 50 多种语言，处理 10 秒音频仅需 70 毫秒，比 Whisper-Large 快 15 倍
- 能力权重：`{"asr": 5, "emotion_asr": 9}`　|　轻量极速，带情感识别，适合实时场景

### 18. tencent/Hunyuan-MT-7B（siliconflow · 翻译）
- 混元翻译模型由 Hunyuan-MT-7B 和集成模型 Hunyuan-MT-Chimera 组成。Hunyuan-MT-7B 是拥有 70 亿参数的轻量级翻译模型，支持 33 种语言以及 5 种中国少数民族语言的互译。WMT25 国际机器翻译竞赛 31 个语言类别中获 30 个第一
- 能力权重：`{"translation": 10}`　|　翻译专项 SOTA

### 19. Kwai-Kolors/Kolors（siliconflow · 文生图）
- Kolors 是由快手 Kolors 团队开发的基于潜在扩散的大规模文本到图像生成模型。通过数十亿文本-图像对的训练，在视觉质量、复杂语义准确性以及中英文字符渲染方面展现出显著优势
- 能力权重：`{"t2i": 10}`　|　文生图主力，中文渲染好

### 20. CogView-3-Flash（zhipu · 文生图）
- CogView-3-Flash 是基于 CogView-3 模型的轻量级版本，拥有 3B 参数量。在多模态任务中表现出色，支持在资源受限的场景中部署
- 能力权重：`{"t2i": 6}`　|　轻量免费文生图，Kolors 的兜底

### 21. BAAI/bge-m3（siliconflow · 嵌入）
- BGE-M3 是多功能、多语言、多粒度的文本嵌入模型。支持密集检索、多向量检索和稀疏检索。可处理超过100种语言，输入粒度从短句到长达 8192 词元的长文档。在 MIRACL 和 MKQA 等多语言跨语言检索基准上取得领先结果
- 能力权重：`{"embedding": 10}`　|　知识库/RAG 检索专用，非生成模型

### 路由调用链示例（由权重自动推导，无需手写 fallback）

```
请求 capability="tool_use"（FC 管线）
→ 具备 tool_use 的模型按权重排序：
   glm-4.7-flash(10) → glm-4-9b(8) → xing4-29b(8) → qwen3-8b(7) → qwen3.5-4b(6) → mimo9b(3)
→ 从左到右依次调用，第一个成功即返回

请求 capability="code"（code_gen 工具）
→ ds-r1-8b(10) → glm-4.7-flash(9) → glm-4-9b(9) → xing4-29b(8) → qwen3-8b(8) → qwen3.5-4b(6) → mimo9b(4)

请求 capability="vision"（image_understand 工具）
→ glm-4.6v-flash(10) → ds-ocr(7) → qwen3.5-4b(6)

请求 capability="long_context"（长文档解析）
→ xing4-29b(10) → qwen3.5-4b(8)

无 capability（普通对话）
→ default 模型 glm-4.7-flash；失败后按 chat 权重降序：
   glm-4.7-flash(9) → xing4-29b(9) → qwen3-8b(8) → ds-r1-8b(7) → glm-4-9b(7) → qwen3.5-4b(6) → glm-4-flash-250414(5) → mimo9b(3)

断网 / 云服务全部不可用（离线路由）
→ 只剩 offline 能力可用：mimo9b(10)（本地运行，不受网络影响）
```

> 说明：
> 1. `GLM-4-Flash`（旧版）与 `PaddleOCR-VL-1.5` 未入表——前者与 250414 重复可二选一，后者是纯 OCR 接口不走 chat；
> 2. `DeepSeek-R1-0528-Qwen3-8B` 不支持 function calling，能力表里**刻意没有 `tool_use`**，FC 管线天然不会选中它；
> 3. `timeout` 建议值：推理模型（R1）120s = 本地模型（mimo9b，受本机算力限制）120s > 长上下文（Xing4.0）90s > 普通 chat 30-60s；
> 4. 语音（ASR 系列）、翻译（Hunyuan-MT）、文生图（Kolors/CogView）、嵌入（bge-m3）走专用接口，在对应 tool 里直接配置；
> 5. `offline: 10` 使本地 mimo9b 在断网场景（云模型全部不可用）成为唯一幸存者——离线路由按此权重选中它；
> 6. mimo9b 各能力权重为保守估计，本地实测后可调整（如实测代码能力不错可把 `code` 提到 5-6，仍不会越过云模型优先级）。
